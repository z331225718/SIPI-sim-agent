## Method

Implement `cdr_lock_v1.rs` in `sipi-channel`: `track_cdr_lock_v1` runs a deterministic clock/data
recovery lock state machine with hysteresis over a timing error sequence (units caller-supplied):
an error magnitude at or below the lock threshold is a good sample, at or above the unlock
threshold is a bad sample, and strictly between the thresholds is neutral. The machine starts
unlocked, acquires lock after `lock_count` consecutive good samples, and while locked loses lock
after `unlock_count` consecutive bad samples; neutral samples reset both counters. `CdrLockTrackerV1`
exposes `observe`/`reset`/`cancel` (cancel freezes the machine until reset). This addresses the
P3B-04 missing semantic `cdr_clock_source_acquisition_lock_reset_and_cancel` as a clean-room
mechanism; no clock source, BER metric, or tolerance profile is introduced. Fail-closed:
non-positive thresholds (`InvalidLockThreshold`/`InvalidUnlockThreshold`), lock threshold above
unlock threshold, zero counts (`InvalidCount`), an empty sequence (`EmptySequence`), and non-finite
errors (`NonFiniteError`) are strictly rejected. An independent Python reference replicates the
hysteresis machine over 4 test cases.

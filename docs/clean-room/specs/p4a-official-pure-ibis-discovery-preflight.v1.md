# P4A Official Pure-IBIS Discovery Preflight v1

## Purpose

This observer-only preflight records one official IBIS-site discovery lead in a
form that cannot silently become implementation material. It does not fetch,
store, parse, execute, or hash the candidate asset.

## Candidate Boundary

The IBIS Open Forum directory lists a file named `sample1(original).ibs`.
The record binds only the HTTPS directory and candidate URLs, the observation
date, and the fact that the directory listed an entry. The file extension is
not evidence that the bytes are a pure IBIS model, contain no algorithmic
attachment, are reproducible, or may be redistributed.

The candidate has `url_only_unresolved` identity and a
`not_observed_from_directory_listing` license/NOTICE state. It is
`discovery_only`, not a required profile, product input, product fixture,
oracle-runnable asset, release input, or parser-test input.

## Promotion Gate

A later, separately reviewed process must establish explicit authorization,
an exact asset identity, and permitted use before it materializes bytes outside
the worktree. This record deliberately contains no local path, content digest,
or asset content, so it cannot serve as that evidence.

## Non-Claims

This preflight does not establish pure-IBIS status, licensing, parser
compatibility, IBIS electrical behavior, numerical acceptance, or release
eligibility.

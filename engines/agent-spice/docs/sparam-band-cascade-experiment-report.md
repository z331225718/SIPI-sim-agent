# S 参数分频段与级联功能项目语料实验报告

日期：2026-07-15。目标是主动暴露问题，不把诊断门限下的 CLI `PASS` 当作生产签核。

## 1. 实验契约

- 分频段 A/B 使用项目 19-port、30-port 原始 Touchstone，固定 effective order 20、完整 826 点、`passivity=check`。
- 输入分别为 `user_input/spara/5power_19port_withcap_122324_202459_11476_DCfitted.s19p` 与 `user_input/spara/5power_30port_wocap_121124_221036_4876_DCfitted.s30p`。
- 所有分频段 case 使用宽松 `--rms-target 1` 只为固定阶次并导出模型；由于最终模型非被动，不可部署。
- 级联二端口由多端口 S 矩阵抽取端口子矩阵，其余端口等价为各自参考阻抗的匹配终端。
- 级联只在输入共同频带内评估，不做带外延拓。

### 观察

- 19p 高段优先、带外权重 0.05：1-2GHz RMS 变化 -59.2%，但全带变化 +21.8%。
- 19p 高段优先、带外权重 0.2：1-2GHz 只变化 -20.1%，说明效果对权重高度敏感。
- 19p 低段优先：0-100MHz RMS 变化 -50.4%，全带也变化 -69.3%；权重改变了极点迁移的局部解，不只是带内/带外交换。
- 30p 高段优先反而让目标 1-2GHz RMS 变化 +16.8%，全带变化 +164.7%；当前算法不保证指定频段单调改善。
- 30p 低段优先把 0-100MHz RMS 变化 -76.4%，但 100-500MHz 变化 +6.8%。
- 所有固定 order 20 模型的 max sigma 都大于 1；本轮只能比较拟合行为，不能作为被动模型签核。

## 4. 暴露问题

1. **P0：优先频段不保证改善。** 30p 的 1-2GHz 优先 case 在相同 order 下目标频段反而变差；target search 目前只在拟合完成后验收，没有与 baseline 比较或自动回退。
2. **P0：级联最终 RMS 没有门禁。** 命令报告 `cascade_mean_rms_error`，但 `PASS` 只依赖逐块门限和级联被动性；用户无法设置 `--cascade-rms-target`。
3. **P0：effective-order mismatch 会拒绝数值可用 block。** mixed 19p/30p 在 max-order 12 时，30p block 已达到 RMS/被动性，但极点裁剪造成 requested/effective order 不一致而失败；max-order 20 才找到合法阶次。
4. **P1：逐块门限与系统误差不一致。** 19p 三块在 RMS 0.01 时第一块失败；放宽到 0.15 后，各块最差约 0.125，但最终级联 RMS 仅约 0.006。严格逐块门禁可能过早拒绝系统级好解。
5. **P1：早停总报告诊断不足。** `block_fit_target_not_met` 只给出 block 名称，最佳 RMS、阶次、enforcement skip 和 order trials 只存在子报告中。
6. **P1：真实被动项目件没有触发收缩 fallback。** 三个成功级联的 sigma 都小于 1，`selected_scales` 全为 1；fallback 目前只有合成单测覆盖，缺少真实边界语料。
7. **P1：关系表达能力有限。** manifest 只能表示每块使用一次的有序 2-port 链，不能声明端口翻转、重复实例、分支或一般多端口连接图。
8. **P2：级联被动性是密集采样检查。** 单块有连续频率证书，但复合链没有连续频率证书；报告需要更醒目标注这一层差异。

## 5. 建议下一步

- 分频段搜索至少同时试 baseline 与 weighted candidate，只在目标频段确实改善且满足带外预算时选择 weighted 模型。
- 增加 `--outside-rms-limit` 与 `--max-full-band-rms-regression`，避免用户只看目标 RMS。
- 级联增加 `--cascade-rms-target`，并把系统级 RMS 纳入收缩候选的选择约束。
- 在级联 block 搜索中明确处理 pole pruning：接受 effective order，或用 effective order 作为缓存/比较键，不要让良好模型因请求阶次不一致被丢弃。
- 早停总报告内嵌失败 block 的最佳 trial 摘要。
- 增加真实近边界被动二端口语料，专门验证 fallback、参考阻抗重归一化和稠密频点遗漏风险。
